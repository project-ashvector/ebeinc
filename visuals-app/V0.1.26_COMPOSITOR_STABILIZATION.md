# ALLTHINGS140Radio Visuals v0.1.26 compositor stabilization

## Root cause hypothesis confirmed by source + screenshot

v0.1.25 moved the generic Stage layer back onto the CSS `stage-screen` mask path. The latest screenshot shows the Stage visible primarily inside the screen-target region while the outside of the canvas is black. That is the opposite of the intended composite and is consistent with WebKitGTK interpreting/rendering the CSS/SVG mask path differently than expected.

The H.264 compatibility runtime is opaque and does not need to carry transparency if composition is structured safely.

## v0.1.26 architecture

The active compositor no longer uses CSS `mask-image` at all.

- Stage Content remains a normal generic media layer.
- Stage role = **Stage Base**.
- Stage Base is rendered below Visual Content.
- Visual Content remains the same generic media layer and is positioned over the Stage's screen opening using the existing transform/Global Frame tools.
- Station logo, Now Playing, presence, reactions and Room Energy remain above both.

This is visually equivalent to looking through a transparent Stage screen, but it avoids WebKitGTK alpha/mask behavior entirely.

## Invariants

- Folder changes never change geometry, role, fit, or stacking.
- Stage Base never uses a CSS mask.
- Stage Base is automatically kept below primary Visual Content.
- Visual Content keeps its existing drag/resize implementation.
- Media source changes do not rebuild the workspace.
- Existing source-fingerprint routes/cache and spawn_blocking media scan remain untouched.
- Original media files are never modified.

## Migration

On first v0.1.26 launch:

- all legacy `stage-screen` masks are cleared;
- Stage-role layers remain Stage-role layers;
- primary Visual Content stays Visual-role;
- Stage Base is placed below Visual Content;
- saved X/Y/Width/Height/Scale/Fit values are preserved.

No user frame is reset.
