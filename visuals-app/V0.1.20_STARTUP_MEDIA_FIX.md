# v0.1.20 startup/media fix

Root cause found in the supplied v0.1.19 source: the code called `updateMediaStatus()` throughout startup/rendering, but the only function that existed was accidentally named `legacyUpdateMediaStatus2()`. The first Visual Workspace render therefore threw a `ReferenceError` inside `applyLayers()`, aborting the rest of startup before selector binding, loopback media-server startup, source assignment, and realtime connection. This exactly matches the observed blank Stage selector with library counts present and both videos stuck at LOADING.

This candidate:
- restores the real `updateMediaStatus()` function;
- starts the loopback media server before the first workspace render;
- clamps Stage and Visual indexes before generating media URLs;
- removes the competing early `convertFileSrc()` Visual assignment;
- reports media-server failure explicitly instead of silently staying on LOADING;
- preserves the Stage Content = duplicated Visual Content transform architecture;
- does not change production or GREEN publishing behavior.
