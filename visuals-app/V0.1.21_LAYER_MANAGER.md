# ALLTHINGS140Radio Visuals v0.1.21 — Production-Style Layer Manager

This release intentionally stops treating `Stage Content` as a privileged/special editor implementation.

## What changed

- `Stage Content` is rebuilt from the same media-layer model as `Visual Content`.
- On first v0.1.21 migration, the old Stage transform is discarded and Stage Content receives a clone of the working Visual Content transform.
- Every media layer uses the exact same direct `<video>` geometry path.
- Media layers can point at any user-selected folder.
- A folder refresh discovers newly-added video files.
- HEVC/MOV/MKV media is converted only when needed into a browser-compatible cached H.264 runtime without geometry filters.
- The localhost media server now has a dynamic registered route table, so duplicated media layers can use arbitrary folders without hard-coded `stage-*` / `visual-*` roles.

## Layer tab management

Right-click any layer tab in the Layers panel:

- Duplicate
- Rename
- Delete
- Bring Forward
- Send Backward

Media layers additionally get:

- Change Media Folder…
- Refresh Media Folder
- Enable/Disable Stage Screen Mask

Source video files are never deleted when a layer is deleted.

## User-recoverable Stage workflow

If Stage Content ever becomes undesirable, the user can now fix it without another code build:

1. Right-click `Stage Content` → Delete.
2. Right-click `Visual Content` → Duplicate.
3. Right-click the duplicate → Rename → `Stage Content`.
4. Right-click the duplicate → Change Media Folder…
5. Select `/home/ebmarah/Videos/at140radio/desktop visuals/stage/`.
6. Right-click it → Refresh Media Folder.
7. Enable `Use Stage screen opening mask` if needed.
8. Resize/drag it with the same transform system as Visual Content.
9. Use Bring Forward if needed so it is above Visual Content.

That is the central purpose of v0.1.21.

## Safety

Production is still locked. The production frozen baseline must not be changed during local validation.
