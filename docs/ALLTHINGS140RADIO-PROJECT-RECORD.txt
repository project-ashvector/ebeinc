5. PRODUCTION RADIO SERVER
--------------------------
Source: /opt/allthings140radio-server/server.py
Current observed version: 0.4.23

The Python server owns authentication, catalog/review queue, AutoDJ, guest/live
handoff, Icecast, and public status.

Completed behavior:
- Persistent FFmpeg AutoDJ encoder connected to the shared Icecast mount.
- Individual track decoders feed the encoder.
- Live guest handoff pauses AutoDJ.
- Watchdog restores AutoDJ after failed/disconnected live sessions.
- Public and authenticated health/status endpoints.
- No-repeat rotation_order plus rotation_seen tracking.
- Eligible tracks are shuffled and reshuffled after the complete cycle.
- Manual next, previous, restart, and play-now controls.

Current health after the queue update:

- DJ app showed 389 catalog entries.

- Health endpoint: http://127.0.0.1:14080/api/health

15. 2026-08-09 PRODUCTION RELEASE 0.5.0
--------------------------------------
Installed production files:
- /opt/allthings140radio-server/server.py
- /opt/allthings140radio-server/radio_extensions.py
- /opt/allthings140radio-dj/dj_app.py

Reliability:
- Watchdog state and bounded recovery counters are exposed in health data.
- A 25-second startup grace prevents false watchdog recovery during normal boot.
- FFmpeg-based silence monitoring uses a configurable duration and does not
  intervene during live handoff or advertisement playback.
- Rotation order, seen IDs, and position persist atomically in
  /var/lib/allthings140radio/rotation-state.json; corrupt or stale state is
  ignored safely when catalog membership changes.
- Structured events now cover track completion/failure, silence, ads,
  recording, archive processing, and watchdog activity.
- Optional severe-failure Discord-compatible webhook configuration uses the
  ALLTHINGS140_DISCORD_WEBHOOK_URL environment variable with cooldown and
  deduplication. No credential is configured by default.

Advertisements:
- Managed MP3 uploads are validated with ffprobe and duplicate names remain in
  the advertisement directory.
- Ads support enable/disable, local preview, manual play, recoverable trash,
  adjustable interval, analysis, Normalize Copy, last-played/play-count data,
  and recent automatic/manual history.
- Normalization changes only the managed server derivative; its prior copy is
  moved to /var/lib/allthings140radio/trash/ads/pre-normalize.

Takeover archive:
- Legitimate browser guest, native Traktor/Mixxx guest, local Traktor, and DJ
  app handoffs automatically start recording only after the live source is
  present. Returning to AutoDJ finalizes the recording.
- Archive metadata is versioned in the existing SQLite station database.
- Local audio: /var/lib/allthings140radio/archives/audio
- Waveforms: /var/lib/allthings140radio/archives/waveforms
- Retention defaults to keep_all. No automatic media deletion is enabled.
- Post-processing generates 720-point waveform JSON asynchronously. Recording
  or waveform failure cannot interrupt live broadcasting.
- Storage provider is local. R2 remains blocked by Cloudflare error 10042.

New endpoints:
- GET /api/public/archive
- GET /api/public/archive/<id>
- GET/HEAD /api/public/archive/<id>/audio (Range supported)
- GET/HEAD /api/public/archive/<id>/waveform
- GET /api/public/alerts
- GET /api/archive (authenticated management inventory)
- POST /api/alerts/test (authenticated admin/manager)
- POST /api/ads/<filename>/analyze
- POST /api/ads/<filename>/normalize

Website:
- Past Streams now requests the public archive API and renders replay cards,
  interactive audio controls, date/duration, and waveform canvases.
- Starting a replay pauses the live station and other replay cards.
- Native transparent alerts support title, message, source, image, optional
  audio, queueing, duration, mobile layout, public polling, custom events, and
  a development test API. No full-page alert iframe is used.
- Service-worker cache is allthings140-radio-v45 and MP4 remains excluded.
